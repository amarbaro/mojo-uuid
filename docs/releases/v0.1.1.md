## What it does

RFC 9562 UUID values, parsing, formatting, and v3/v4/v5/v6/v7/v8 generation for Mojo with CPython constructor error texts and exact 16-byte inline layout.

## Highlights

- Parsing a `urn:uuid:` or `{...}` UUID takes 10 ns instead of 679 ns; a hyphenated one 9 ns instead of 50 ns (CPython 3.14.9: 777 and 929 ns).
- `UUID` can be a `Dict` or `Set` key and can be printed: it was not hashable or writable in v0.1.0.
- Parsing now accepts what CPython's `uuid.UUID(hex)` accepts: Unicode spaces and Unicode decimal digits around or inside the 32 digits.
- `str()` 76 -> 29 ns, `hex()` 47 -> 27 ns, `urn()` 105 -> 33 ns, `bytes()` 32 -> 5 ns and `bytes_le()` 40 -> 5 ns.

## Changes

### Added
- `UUID` conforms to `Comparable`, `Hashable` and `Writable`: `Dict[UUID, V]`, `Set[UUID]`, `print(uuid)`, `String(uuid)`.
- `tools/gen_unicode.py` and the generated `src/uuid/_unicode.mojo` (Unicode 16 tables).
- Differential rows against CPython for every accessor, name UUIDs, `uuid8`, and replayed v6/v7 state.

### Changed
- Parsing and formatting run in place with SIMD and no heap block except the returned `String`.
- `UUID.from_int(text)` follows `UUID(int=int(text))`: base-10 grammar, invalid text names the literal.
- `uuid8` draws one 16-byte entropy block instead of up to three `getrandom` calls.
- Scripts no longer use `systemd-run` or sibling paths; `scripts/env.sh` resolves mojo and mojo-hashlib.

### Fixed
- `int()` whitespace: U+001C..U+001F were stripped (CPython keeps them) and the non-ASCII Unicode spaces were not.
- Unicode decimal digits were rejected where CPython reads them.
- Error texts escaped only a few codepoints; they now follow `str.isprintable()` (`\xNN`, `\uNNNN`, `\UNNNNNNNN`).
- `from_int` reported "out of range" for non-digit text and ignored signs, spaces and underscores.
- The tracked `src/uuid/hashlib` symlink (dangling in any clone, a second hashlib copy in the package otherwise) is gone.

## Known limits

- Linux only (libc `getrandom`, `clock_gettime`), little-endian hosts.
- `from_int` does not reproduce CPython's 4300-digit decimal limit; UUID1/2 and SafeUUID are not provided.
- One-shot `uuid6()`/`uuid7()` are not monotonic across calls; use the generator types.
- Unicode tables are Unicode 16 (CPython 3.14); a CPython with other tables can differ on newly assigned codepoints.

## Upgrade / run

```
mojo run -I src -I ../mojo-hashlib/src examples/quickstart.mojo
```
No API removed. `from_int` now rejects text that is not a decimal integer (it did before, with another message).
