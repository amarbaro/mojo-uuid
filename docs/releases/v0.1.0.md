# mojo-uuid v0.1.0

**Released:** 2026-11-07 · **Commit:** the one tagged `v0.1.0` · **Previous:** first release

## What it does

RFC 9562 UUID values, parsing, formatting, and v3/v4/v5/v6/v7/v8 generation for Mojo with CPython constructor error texts and exact 16-byte inline layout.

## Highlights

- Values occupy 16 inline bytes (`UInt128`) with zero heap allocation per UUID value.
- Parse 19x faster than CPython (44 ns/op vs 837.8 ns/op) and format 4x faster (97 ns/op vs 391.9 ns/op).
- Complete RFC 9562 test vector compliance across Appendix A.2-A.6, Appendix B.1-B.2, Nil, Max, and namespaces.
- Exact CPython 3.14 constructor error kind and message parity (`TypeError` and `ValueError`).
- Fuzz differential verified across 5,000 random inputs against CPython with 0 differences.
- 13 compiling behaviour mutants in the core library, all killed by the test suite.

## Known limits

- Convenience `uuid6()` and `uuid7()` helpers are not monotonic across calls; use caller-owned `UUID6Generator` and `UUID7Generator` instances for monotonic sequences.
- Default `uuid6()` node generation uses random bytes via libc `getrandom`, without hardware MAC lookup.
- UUID1/2, SafeUUID, arbitrary-precision integer arguments, and full Unicode decimal digits are outside this interface.
- Python object identity is not replicated; `UUIDError` is a Mojo value struct (`Copyable`, `Movable`, `Writable`), not a Python exception class.
